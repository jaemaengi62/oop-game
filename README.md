# OOP Game

## 문제 정의

is-a와 has-a 관계를 코드로 표현하는 방법이 익숙하지 않아 `Dragon = Monster()`처럼 작성했습니다. 체력과 아이템 객체를 다시 감싸거나 메서드의 반환값을 빠뜨리면서 체력 계산, 무기 장착과 강화가 의도대로 동작하지 않았습니다.

## 해결

- 종류 관계는 `class Dragon(Monster):`처럼 상속(is-a)으로, 소유 관계는 `self.hp = HP(150)`처럼 객체를 속성으로 가지는 방식(has-a)으로 표현했습니다.
- 이미 생성된 객체는 다시 감싸지 않고 그대로 저장했습니다.
- 공격 로그와 꺼낸 아이템을 각각 `return log`, `return item`으로 반환했습니다.
- `attack()` 한 번에 한 번만 공격하고, 전투 시나리오에서 턴을 반복하도록 나눴습니다.
- 경험치를 누적한 뒤 필요 경험치를 차감해 여러 번의 레벨 업을 처리했습니다.

## 설계도

상속 관계(is-a):

```text
GameObject
├── Character
│   ├── Warrior
│   └── Wizard
└── Monster
    ├── Slime
    ├── Golem
    └── Dragon

Item
└── Weapon
```

객체를 속성으로 가지는 관계(has-a):

```text
Character
├── hp        → HP
├── weapon    → Weapon → Element
├── level     → Level
└── inventory → Inventory → 아이템 목록(Item / Weapon)
```

## 정량 결과

| 항목 | 확인한 결과 |
| --- | --- |
| 골렘 처치 후 성장 | 누적 경험치 150에서 100을 소비해 Lv.2, EXP 50, 최대 HP 170 |
| 무기 강화 | 강화석 1개 소비, 물의 창 공격력 25 → 30 |
| 보스전 | 물의 창 공격력 30 × 상성 2 = 피해 60, 체력 300인 보스를 5턴에 처치 |
| 최종 성장 | 보상 경험치 500을 더하고 200·300을 차감해 Lv.4, EXP 50 |

## 확장 계획

현재 전사와 마법사는 공통 `attack()`을 그대로 상속합니다. 앞으로 각 클래스에서 공격 방식을 오버라이딩하고, 동일한 호출 코드로 처리하는 다형성을 적용할 계획입니다.

또한 `Skill`과 `Armor`를 캐릭터에 연결하고 몬스터의 반격을 추가해 전투 기능을 확장할 계획입니다.
